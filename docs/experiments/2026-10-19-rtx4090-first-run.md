# Lite R-CNN — RTX 4090 첫 전체 COCO 학습 결과

## 실행 범위

- 모델: Lite R-CNN, MobileNetV3-Large + 2회 BiFPN + Faster R-CNN RPN/RoI head
- 데이터: COCO 2017 train 118,287장, 전체 `val2017` 5,000장
- 입력 최대 변: 640px; train batch 8, validation batch 4; AMP 사용
- 학습: 36 epoch 완료, epoch당 14,786 batch iteration, 총 532,090 optimizer update
- 결과 폴더(학습 머신): `outputs/coco_4090/`; `best.pth`와 `last.pth`는 이 대화에 첨부되지 않아 현재 저장소에서는 직접 재평가할 수 없음

최고 AP@[.50:.95]는 0.256581(epoch 27)입니다. epoch 25 이후 AP는 약 25.4–25.7% 범위에서 정체했고, 마지막 epoch까지 train loss는 감소했지만 validation AP는 최고치를 넘지 못했습니다. 즉, 최적화는 계속 진행됐지만 일반화 성능은 plateau에 도달한 모습입니다.

## 진단과 해석

- **약점은 작은 객체와 높은 IoU 구간입니다.** 최고 epoch에서 AP-small 10.06%, AP-medium 28.49%, AP-large 38.70%였습니다. AP50 45.33%와 AP75 25.77%의 차이도 커서, 박스 정밀도와 작은 객체 검출을 우선 조사할 근거가 있습니다.
- epoch 36에서 이미지별 최고 class-agnostic IoU 평균은 0.8748, class-matched IoU 평균은 0.8627이며 5,000장 중 4,890장에 같은 class로 IoU≥0.5인 예측이 하나 이상 있었습니다. 이 값은 이미지당 최고 한 쌍만 보는 진단 통계라 recall/AP를 뜻하지 않습니다. COCO AP가 낮은 이유를 박스 생성, 중복 검출, 점수 순위, category별 오류로 더 나눠 봐야 합니다.
- 샘플 이미지 `000000000776.jpg`의 GT에는 teddy bear 3개와 bed가 있습니다. 모델은 teddy bear 검출 여러 개와 couch 오검출을 냈습니다. 따라서 이 예시 하나만으로 전체 클래스 붕괴를 주장할 수는 없지만, 중복 검출과 혼동 사례를 시각 점검할 필요는 있습니다.
- 이 성과는 전체 COCO 검증으로 측정한 실질적인 학습 결과지만, 프로젝트 목표로 둔 mAP 60에는 도달하지 못했습니다. Faster R-CNN/YOLO26과의 수치 비교는 팀원 측 동일 조건 결과가 있어야 하므로 여기서는 결론 내리지 않습니다.

## 다음 Lite R-CNN 실험

1. 사용자 GPU의 `history.jsonl`, `config.yaml`, `best.pth`를 한 run 폴더로 함께 보존하고 `evaluate_coco.py` 결과 JSON을 생성해 재현 가능한 기준선을 고정합니다.
2. COCO 객체 크기 분석에서 640 입력 기준 `sqrt(area)` 25백분위 26.8px, 90백분위 257.2px였습니다. 현재 anchor base size 32–256px 설정에 P3 16px 및 P5 512px anchor를 추가하는 후보를 한 번에 하나씩 비교합니다. 이는 아직 가설이며 proposal recall과 full-val AP로 채택 여부를 판단합니다.
3. 같은 seed·입력 크기·학습 schedule을 고정한 상태에서 anchor 후보별 AP-small, AP75, AR@100 및 epoch 시간을 기록합니다. 개선이 없으면 원래 설정으로 되돌립니다.

이 보고서는 사용자가 붙여넣은 터미널 로그와 저장소의 COCO annotation으로 작성했습니다. epoch 1–13의 상세 JSON 줄은 붙여넣은 로그에 포함되지 않았습니다.
