# Lite R-CNN v3 design and run record

## Motivation from v2

The best v2 checkpoint reached 28.82 AP@[.50:.95] on all 5,000 COCO val2017 images at 640 pixels. AP-small was 10.99%, versus 31.76% AP-medium and 44.52% AP-large. The v2 MobileNetV3 pyramid starts at stride 8, so small objects have no stride-4 feature level. The v2 run also disabled distillation and trained its RPN and RoI detector heads without COCO detection-teacher supervision.

## v3 architecture

Lite R-CNN v3 retains the Faster R-CNN training and inference stages: anchor-based RPN, proposal NMS, RoIAlign, class/box predictor, and per-class NMS.

```text
MobileNetV3-Large ImageNet/v2 initialization
  C2 stride 4 ─┐
  C3 stride 8 ─┼─ 64-channel top-down Lite FPN (lateral 1x1 + separable 3x3) → P2-P5
  C4 stride 16 ┤
  C5 stride 32 ┘
                              P5 ── max-pool → P6 ── max-pool → P7 (RPN only)
                                      ├─ 6-level anchor RPN (8px–256px, 3 anchors/location)
                                      └─ P2-P5 7x7 RoIAlign → per-RoI 1x1 projection 64→32
                                         → 7x7 pooling + FC 1568→256 → cls/box
```

The single-pass FPN replaces v2's two-pass 96-channel BiFPN. Adding P2 increases high-resolution work, so FPN width is 64 and the RoI projection is 32 channels. Projection runs on pooled RoIs rather than every position of every feature map. Relative to v2's 7×7×64 RoI input, the v3 FC sees half as many input features. The RPN uses one anchor scale and three aspect ratios at each level (3 anchors/location, versus v2's 9); P6 is a cheap max-pooled level for coarse/large proposals, while RoIAlign uses P2-P5.

At 640 pixels, v2's P3-P5 maps have 8,400 total locations × 9 anchors = **75,600 anchors/image**. v3's P2-P7 maps have 34,125 locations × 3 anchors = **102,375 anchors/image** (**35.4% more total anchors**). The lower head width and per-location anchor count do not guarantee lower end-to-end latency because P2 adds many high-resolution locations. The first full-run comparison must record actual batch-1 p50/p95 latency and peak memory alongside AP-small; keep v3 only if its measured accuracy benefit justifies the runtime cost.

Training transfers only `backbone.body.features.*` from the v2 checkpoint. New FPN/RPN/RoI modules start fresh. The frozen COCO Faster R-CNN ResNet50-FPN teacher supplies stride-aligned features and teacher RoI logits on the student's sampled proposals. The teacher is not part of inference.

## Reproduction

```powershell
python scripts/train.py --config configs/coco_v3.yaml --device cuda --init-backbone outputs/coco_4090_v2/best.pth
```

Preset: seed 42, COCO train 118,287, full val2017 5,000, 640-pixel max side, batch 4, AMP, 48 epochs, milestones 32/42. Outputs go to `outputs/coco_4090_v3/`. The first run may download ImageNet MobileNetV3 and COCO Faster R-CNN teacher weights if they are not cached.

## Implementation checks (2026-10-28)

- A synthetic 320×320 inference completed through backbone, P2-P7 RPN, RoIAlign and postprocessing. The six RPN levels each reported three anchors/location. The randomly initialized detector returned zero boxes, as expected before training.
- A synthetic one-image student/teacher training forward matched student maps `0/1/2/3` to teacher maps `0/1/2/3`; supervised losses, feature KD and RoI KL were all finite.
- v2 `best.pth` loaded strictly into its original v2 factory with no missing/unexpected keys. For v3 initialization, all **308/308** MobileNetV3 feature-extractor tensors from v2 matched by key and shape.
- Instantiated v3 has **3,622,918 parameters**, 13.5% fewer than v2's 4,187,700. This is a parameter-count comparison only; FLOPs, memory use and inference latency remain unmeasured.
- These checks establish code-path and checkpoint-transfer compatibility only. No COCO training, AP validation, accuracy gain or latency result has been measured for v3.
